## 検証
- プレビュー: previews/（A=合成8枚、B=単体5枚）、拡大クロップ: crops/（15枚）。
  全枚目視済み。合格基準（軸は垂直・傘面は頭の真上・フックは握りの下・
  袖は服と地続き・二重腕なし・顔に掛からない）を全枚満たす。
- B群は元絵との差分チェック実施（sleeve_arms_report.json）。
  折りたたみ3枚は顔ゾーン平均差 6〜14 で誤差レベル。
  開いた傘2枚（rank5／raincoat）は顔ゾーンの数値が高い（82／106）が、
  これは傘が入って人物の画面内位置が下にずれたためのゾーン比較の
  ズレで、目視では顔の描き直しは確認されていない（目・口・髪は元絵通り）。
- 落とした案:
  - カーディガン＋開いた傘 1回目: 編集で傘の軸が消え腕の輪郭が波打った
    →「軸は切れ目なく維持」を強指示して再生成し合格。
  - ポロ＋日傘 1回目: 肌がベージュ／ピーチ色に変色 → 肌色 #C0EAFC を
    明示して再生成し合格。
- 既知の弱点（汎用レイヤー版から引き継ぐ性質）:
  - 日傘: 腕が胴の輪郭の少し外側に付く（グリップ位置は手に一致）。
  - うちわ: 腕ストリップの上端は平らな切り口で髪の横に出る。
  - 折りたたみ: プレビュー（人物が画面いっぱい）では傘の先が下端に
    かかる。アプリ側は人物が小さく入るため収まる想定。

## 手順メモ
- 生成は全て元絵を下敷きにした編集生成（media.generate_image）。
  A群の下敷きは汎用腕レイヤーの生成元webp＋トップスPNG（袖リファレンス）。
- キーイングは tools/key_assets.py の key_image を流用
  （key_sleeve_arms.py）。グリップ座標は自動検出が不安定なため
  キーイング済みPNGの目視で決定（汎用版と同じ方式）。
