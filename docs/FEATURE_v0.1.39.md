# FEATURE v0.1.39 — 空が呼吸する（天気のアニメーション）

本人の指示（2026-11-28）：「天気はアニメーションにしたい。
リアルでヌルヌル動く雨や、日差しなどを目指して」。
v0.1.38 で天気・時間に連動するようになった空を、今度は
実際に滑らかにアニメーションさせた。静止画の雨筋・雪片では
なく、生きて動く空にする。

## 前提：土台は v0.1.9 からあった

SkyView は v0.1.9 以来 Choreographer 駆動のフレームループを
持ち、雲の漂い・雨・雪・霧は既に動いていた。本版の仕事は
その土台の上での4点： **滑らかさ（フレームレート）**、
**再現性（純粋関数化）**、**日差しと星の動きの追加**、
**止める逃げ道（設定）**。パレット・天気キャスト・
コントラストの定数は一切変えていない。

## 変更内容

### 1. フレーム駆動：vsync 駆動へ（約30fps キャップの撤廃）

- 従来は `postFrameCallbackDelayed(33ms)` で約30fpsに
  制限していた。雨は 470〜760dp/秒で落ちるため、30fps では
  1フレームに 16〜25dp 進み、目に見えてカクついた。
- 本版は通常の `postFrameCallback` でディスプレイの
  vsync に同期する（60Hz 端末で 60fps、高リフレッシュ
  レート端末ではそれ以上）。運動は従来どおり Δt ベース
  （フレーム時刻の差分を積算、Δt は 0.1 秒でクランプ）。
- 電池配慮はレートを絞るのではなく、ループの**ゲート**で
  担保する（下記「停止条件」）。

### 2. 粒子の純粋関数化（時刻パラメータで決定的に描ける）

- 雨・雪の位置は従来、フレームごとに座標を加算する
  破壊的更新だった。本版はシード（初期位置・速度・長さ）
  だけを保持し、位置は描画時に **animTimeSec の純粋関数**
  として計算する：
  - 雨： 落下距離 dist = 速度×密度×t÷画面高。y は 1.1 高の
    ラップ周期（画面上端の少し上→地面の下）で割り、ラップ
    回数ごとに x を 0.37 ずらす（状態なしで「新しい列」に
    見える）。傾き（風）は雨滴ごとの長さから導く
    （0.14〜0.28、長い雨滴ほど寝る）。
  - 雪： y は 1.06 高のラップ周期、横揺れは従来どおり
    sin(0.7t＋位相）×8dp。
  - 雲・霧は従来から時刻の関数だったものを animTimeSec へ
    統一。
- t=0 の配置は従来の初期配置と完全に同一になるよう設計
  した（シードの乱数消費順も不変）。このため動きを止めた
  静止画は v0.1.38 と同じ絵になり、ゴールデンは雨の
  フェード分（後述）だけを再記録した。
- テスト可能性： `SkyView.animTimeSec` はテストシーム
  （`clockMillis` と同じ型）。スクリーンショットテストは
  時刻をピンして任意のフレームを決定的に描ける。実時刻で
  ゴールデンが揺れる要素は増えていない。

### 3. 雨のフェード（出現・消滅を消す）

- 雨筋は上端付近（y −0.05〜0.05）でフェードインし、地面
  付近（y 0.90〜1.02）でフェードアウトする（高さ方向の
  smoothstep）。ラップ境界での出現・消滅が見えなくなる。
- α の上限は従来値（ライト 92／ダーク 82）のまま。フェード
  は弱める方向にしか働かない。

### 4. 日差し：太陽・月のグローの呼吸

- 太陽（と月）のグローが 7 秒周期で穏やかに呼吸する：
  `breathFactor(t) = 1 − 0.05×(1 − cos(2πt/7))`、
  α と半径（最大 −5%）に掛ける。周期 7 秒・振幅 ±5% は
  「光がゆらめく」知覚の下限寄りで、ギラつかせない。
- **コントラスト保全の設計**： 係数は 0.90〜1.0 の範囲で
  しか動かず、t=0 では正確に 1.0。つまり全アニメーション
  フレームは「走査済みの静止画の定数以下」のグローしか
  描かない。v0.1.38 の再走査の最悪ケースが全フレームを
  引き続き上限として拘束するため、再走査なしでゲート
  （全バリエーション 4.5:1 以上）が維持される。結論の
  背後の環境グロー（文字が直接乗る）は呼吸させず静止の
  ままにした。

### 5. 夜：星のまたたき

- 星ごとにシードから導いた周期（約5.7〜12.6秒）と深さ
  （0.30〜0.60）で、α がコサインの swell としてゆっくり
  満ち欠けする。呼吸と同じく係数は 1.0 以下・t=0 で 1.0。
- **点滅ではない**： オン／オフの切替はなく、周波数は
  0.1Hz 級、振幅も α の最大6割減まで。§6 の「点滅・明滅は
  一切しない」は稲妻のような閃光と高速な明滅への禁止で
  あり、本版でも雷は稲妻を描かない（従来どおり暗い雲＋
  強い雨＋最も深いキャストのみ。フラッシュは入れない
  判断を明記する）。星の swell は太陽の呼吸と同じ
  「ゆっくりした明るさのうねり」で、規律の精神（穏やかさ）
  の内側にある。

### 6. 雲

- 従来どおり全天気でゆっくり流れる（数分で横断）。量と
  速さの天気連動は v0.1.9 以来のまま（雲量で目覚める数が
  変わる）。本版では時刻源を animTimeSec に統一しただけ。

## 停止条件（電池とアクセシビリティ）

フレームループが回るのは全条件を満たす時だけ
（`SkyView.updateLoop` が一元判定）：

- Activity が resumed（MainActivity の onResume で開始、
  onPause で停止）；
- View が attach され、表示状態（自身と祖先が VISIBLE、
  ウィンドウ可視）であること。可視性・ウィンドウ可視性・
  detach の各イベントで再判定し、コールバック内でも
  `isShown` を毎フレーム確認して取りこぼしを止める；
- ウィンドウフォーカスがあること（喪失で停止、復帰で
  再判定）；
- 端末の「アニメーションを無効化」（Animator duration
  scale = 0／animators 無効）でないこと、省電力モードで
  ないこと（従来の reduced-motion 判定を継承）；
- アプリ内設定「空の動き」がオンであること（新設）。

いずれかで止まった場合は、その状態の空の静止画になる
（v0.1.38 相当）。動きは情報の担い手ではないので、静止画
でも天気と時刻は色と要素の配置で完全に伝わる。

## 設定「空の動き」

- 設定画面に新セクション（太陽アイコン＋「空の動き」、
  説明「オフ＝空は静止画になります」、セグメント
  オン／オフ）。既定オン。pref キー `skymotion`。
- 切替は即時に生きている空へ反映される（`applySkyMotion`）。
- 確認は自動テスト（settings_skyMotionToggle）で実施：
  セクションの存在、既定オン、オフ→オンの永続化まで検証。

## 粒子数と描画の設計値

- 雨： プール 90 本、表示は雨レベル×30（30／60／90 本）。
  速度 470〜760dp/秒、長さ 9〜15dp、線幅 1.4dp。
- 雪： 60 個、速度 24〜44dp/秒、半径 1.5〜3.1dp。
- 雲： 7 個（各5 blob）、横断は数分オーダー。
- 星： 70 個（ダークのみ、上部40%）。
- 粒子は全て init で事前確保したプールの再利用。粒子
  レイヤーの Paint はフィールド保持し、onDraw 内で粒子
  用のオブジェクト生成はしない。

## 変えていないもの

- A案の世界観、天気キャストのパレットとアンカー、
  コントラストの全定数（アニメーションの変調は全て
  「走査済み静止値以下」に設計）。
- B5 構造、全ロジック・判定ルール・夜間明日モード
  （19時）・データ取得・キャラクター素材。
- ウィジェット（Android の制約どおり静止のまま、4面を維持）。

## 残った課題（実機待ち行列）

- ヌルヌル感の最終判定は実機のフレームレートと描画
  負荷に依存する（この VM では測れない）。特に高
  リフレッシュレート端末での vsync 駆動時の電池消費と、
  ソフトウェア描画端末での描画コストは実機確認待ち。
  悪化が見えた場合の調整代は「粒子数の削減」「グロー
  半径の縮小」「端末性能に応じたレート上限の復活」を
  候補として残す。
- 呼吸・またたきの「穏やかさ」の加減（周期7秒・振幅
  ±5% が実際にどう感じるか）は実機スクショ／実機での
  確認待ち。
- 雪の日に雨筋も薄く混ざる件は v0.1.38 からの既存仕様
  のまま（本版では変更していない）。
- ウィジェットのプレビュー模式図 widget_preview.png は
  旧来のまま（実表示は4面）。
