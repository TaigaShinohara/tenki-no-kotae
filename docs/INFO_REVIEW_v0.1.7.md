# 天気のこたえ — 情報最小化の見直し記録 v0.1.7

- 実施： 2026-11-19。本人の指示「次に情報を最小限にするスキルを使って全体を見直して」。
- 物差し： minimal_information_design スキル（核の8原則）。一言の物差しは「読まなくても分かるか。3秒で次にすることが分かるか」。
- 前提： 見た目（Simple Glass の色付きガラス・土台・光）は v0.1.6 の形を正とし、壊していない。色の役割・ガラス面の値・Rules の出力文言（結論／服装／傘／日焼け止め／気圧／帰り／明日の文章）はすべて不変。今回変えたのは「何を・どこに・どの形で出すか」だけ。
- 主役（画面ごと、meaningful 側の決定を前提とする）： ホーム＝結論1文／詳細＝（主役なし）答えの裏付け／設定＝（主役なし）自分の感覚の申告／読み込み＝「取りにいっている」こと／エラー＝次にできること。

## 数え方（削減前後で同一）

- 要素： 利用者が「1つの意味のまとまり」として認識する単位で数える。カード・ラジオグループ・タブバーはグループで1つとし、子要素は数えない。時間別の行群は「枠を1つ」と数え、列数は選択肢数ではなく1行あたりの項目数として別に記録する。
- 可視文字数： 空白を除く全文字（句読点・記号を含む）の概算。代表状態で数える： 寒い日（体感 3〜7℃帯）、気圧カード表示あり、寒暖差の補足行あり、明日あり、予備モードなし、詳細は通常源（Open-Meteo）。結論など Rules の文章は日によって変わるため、ホームの合計は代表例での値。
- タブバー（3ラベル・10文字）は全画面共通のため、各画面の合計に含めない（ホームのみ参考として併記した v0.1.5 までの数え方とは異なる。比較は本書内で完結させる）。

## 検討して不採用にしたもの

- **時間別への等幅フォント採用**： 数字の桁を揃えれば列が整うが、ART_DIRECTION §5「書体は端末既定の1系統のみ」に反する（原則7： 語彙を増やさない）。列を2つ減らす方を採った。
- **タブのアイコン化**： 「数値で見る」に意味の固定したアイコンがなく、漢字記号の二重表記（v0.1.6 で本人が間抜けと評価）を繰り返す。不採用。
- **服装カード補足文の分割・削減**： 上表のとおり、消すと判断が増える側の情報だったため残した。
- **日の出／日の入りの削除**： 詳細の逃がし先としての網羅を優先し B で残した（上表）。
- **詳細・設定への段階表示の拡大**： タブ遷移は「行き先が分かっている繰り返し操作」であり、段階表示は待たされる感覚を作るだけ（原則6「意味のない動きは入れない」）。ホームの新規取得時だけに限定した。

## 検証

- **3秒テスト**： 未実施（初見の人間がいない）。未確認として残す。実機が得られたら最初に確かめる項目は「ホームで結論だけが目に入るか」。
- **無読テスト**： 未実施（同上）。未確認。
- **ぼかし見テスト**： 仮判定・合格。コード上の照合で、ホームは結論（最大・唯一の色文字）が浮かぶ構成に変化なし。タイトル削除で詳細・設定はさらに静かになった。
- **届きやすさ（親指）テスト**： 仮判定・合格。主要アクション（エラーの再試行ボタン1つ）とタブバーは下部／画面内の届く位置にあり、変更なし。危険な操作は存在しない。
- **折りたたみテスト**： 対象なし（今回、新規の折りたたみは作っていない。B ランクは条件表示と詳細画面への集約で処理した）。
- **到達確認**： 上表のとおり実施（コード上の到達経路で確認）。
- **アクセシビリティ確認（静的）**： 合格範囲はコードで確認できる分のみ。コントラストは色・面を変えていないため v0.1.6 の再走査結果（全ゲート合格）がそのまま有効。タッチターゲットは不変（タブ 56dp、ラジオ・ボタン 48dp 以上）。段階表示は OS のアニメーション無効設定で即時表示に切り替わり、最終状態だけで情報が完全に伝わる。アイコンのみの要素は今回も作っていない（読み上げ名の問題は新規に発生しない）。文字拡大時のレイアウトは実機未確認。
- **語彙テスト**： 合格。新しい色・形・フォントサイズ・角丸は追加していない。削除と移動のみ。
