# 天気のこたえ — 情報最小化の見直し記録 v0.1.10（視覚的な見やすさ版）

- 実施： 2026-11-19。本人の指示「minimal information スキルで視覚的に見やすくしてみて」。
- 物差し： minimal_information_design スキル（核の8原則）。ただし今回の軸は v0.1.7／v0.1.8 の「文字量」ではなく **見た目の読みやすさ** — 視覚階層（最初に目が行く先が結論か）、要素同士の競合（動く空とカード、アイコンと文字）、余白と整列のリズム、色の数と役割、アイコンの大きさ・位置の統一感、にぎやかさの総量。
- 守ったもの： 本人が直前に指示して入れた要素（背景の空アニメーション、アイコン体系）は **消していない**。弱める・整えるだけにした。ロジック（Rules／WeatherApi／MetApi、更新日時でも無変更を確認）と Rules の文言、色の役割（その日の色1色・7帯）、ガラス面・ピル・ベタの値は不変。
- 主役（画面ごと、従来の決定を維持）： ホーム＝結論1文／詳細＝（主役なし）答えの裏付け／設定＝（主役なし）自分の感覚の申告／読み込み＝「取りにいっている」こと／エラー＝次にできること。

## 残したもの（理由つき）

| 要素 | 理由 |
|---|---|
| 空のアニメーションそのもの（雲・雨・雪・霧・星・天体の動き） | 本人が直前に指示して入れた要素。今回の指示は「見やすく」であって「静かにしすぎ」ではない。存在感の調整（量・濃さ・速さ・置き場）に留めた |
| 雨・雪が画面全面に降ること自体 | 空が全面である以上、カードの背後に降るのは構造上避けられない。αと速さで「気にならなさ」を作る方を選んだ |
| 結論の背後の環境グロー（0.30w, 0.17h、半径230dp） | v0.1.6 で「結論の背後に光を置く」と決めた意図的な主光であり、結論の浮かび上がりそのもの。弱めると主役の階層が痩せる |
| タブ・主ボタンのベタの角丸 26dp | 主ボタン（高さ52dp）では 26dp がちょうど全丸（高さの半分）で正。タブ（56dp）では厳密には 28dp が全丸だが、26との見た目の差は判別できず、土台ガラス（24dp）との兼ね合いでも現行が安定しているため、 churn を避けて残した |
| アイコンの色の使い分け（ホーム＝ink、詳細の見出し・統計＝補助色、設定＝ink） | 各画面の中では一貫している（詳細は「静かな裏付け」という §7 の方針で、ラベルとアイコンが同じ補助色に揃っている）。画面をまたぐ不統一ではなく、画面ごとの役割の差として残した |
| 雪の α190・個数60 | 雪は遅く（24〜44dp/秒）小さく、季節も限られる。雨と違って周辺視野を引く速さが無いため、今回は触らない |
| 詳細のグラフ・気圧スパークライン、設定のセグメント／チップ | v0.1.8 で形にしたばかりで、今回の監査軸（階層・整列・語彙）でも問題が出なかった |
| 段階表示（stageIn） | 空の動きと同時に走るのは新規取得時の一度だけ（約0.9秒）で、競合は一時的。原則6の案内としての意味が勝つ |

## 視覚階層の前後（「最初に目が行く先」）

- **ホーム**： 前後とも最初は結論（34sp・その日の色・画面最上部）で不変。変わったのはその「次」の体験 — 以前は結論の周囲で雲と雨と太陽グローが同じ強さで主張し、カードの中でもアイコンの高さがばらついて目の休まる軸が無かった。変更後は、結論の周囲（上部の帯）に天体と雲が寄り、カード群の背後は静かになり、カード内はピル → アイコン（全カード同じ高さ）→ 主文という左列の軸ができた。視線の流れは「結論 → 左列をまっすぐ下へ」が設計どおりになった（コード上の照合による仮判定）。
- **詳細**： 前後とも要点カードのヒーロー数字（34sp）が最初。気圧見出しの絵がその日のレベルと一致するようになり、「絵と数字の矛盾で一瞬止まる」が無くなった。折りたたみ見出しは形がトークンに揃い、カード群との境目で浮かなくなった。
- **設定／読み込み／エラー**： 階層そのものは不変。空側の調整で背景の主張だけが下がった。

## コントラスト再走査

v0.1.9 と同じ再現モデル（Kotlin の色計算＝チャンネル毎 lerp＋切り捨て、sRGB 空間での source-over 合成、WCAG 輝度）で、新定数（雲 α80／28 ほか）を使い再走査した。環境グローの扱いだけ物理寄りに精密化した： グローは中心 (0.30w, 0.17h)・半径 230dp の放射グラデであり画面下部には届かないため、空に直置きの要素は「要素の領域からグロー中心への最短距離（360×800dp 基準）における減衰後の α」で評価し、ガラス面の要素は従来どおりピーク重なりで評価した（モデル検証： 空と無関係な既知の律速＝ベタ上文字 4.58、ピル 4.59 は v0.1.5／v0.1.9 の記録値と一致）。

- 範囲： 7帯×明暗×位相格子（dayness 5段×warm 3段）×全23要素×配置×最悪重なり（グロー／天体／雲2枚）
- **結果： 209,370 チェック全合格**
- 4.5 ゲートの最弱： **4.58**（ライト・寒い帯、ベタ上の文字 — v0.1.5 から既知の律速で空と無関係）
- 3.0 ゲートの最弱： **3.01**（結論、ライト・寒い帯、dayness=0 かつ warm=1 という物理的に到達しない組合せ＋雲2枚重ね）
- 空に直置きの補助文字の最弱： **4.94**（ヘッダー地点名、ダーク・あたたかい帯、グロー減衰＋雲）
- 雲 α の引き下げによる数値マージンの変化は最小だった（結論の最弱 3.01 は旧定数でも同じ値、補足行 3.06 → 3.07）。今回の変更の効果はコントラストではなく「見た目の静かさ」側にある — ゲートは静かさも測れない（v0.1.6 の教訓の裏返し）ため、効き具合の最終判定は実機に残す。
- 雨・雪・星・霧は細線・小要素として走査対象外（霧の α はさらに下げたので、対象外の前提は強まる方向）。

## 検証

- **単体テスト**： 既存26件・無変更で全合格（Gradle コンパイル＋JUnit 手動実行、実 org.json jar を android.jar スタブより前に置く従来方式）。
- **ビルド**： assembleRelease 成功（build.sh、Gradle 8.9・in-process）。
- **署名**： apksigner 検証済み、SHA-256 = FC:F7:43:C2:38:8C:8A:E9:F5:9F:69:2B:49:75:5F:47:9A:05:06:20:8D:BF:B7:A5:6E:E2:D3:6D:80:FE:F8:3F（従来と同一。納品コピーはビルド成果物と md5 一致を確認）。
- **バージョン**： aapt で versionName 0.1.10 / versionCode 11 を確認。
- **3秒テスト／無読テスト**： 未実施（初見の人間がいない）。未確認として残す。実機が得られたら最初に確かめる項目は「ホームで、結論の周りが前より静かに感じるか（特に雨の日）」。
- **ぼかし見テスト**： 仮判定・合格（コード上の照合）。ホームは結論が浮かび、カードの左列に軸ができた。詳細・設定は変更前から静かで、その静けさを壊していない。
- **届きやすさ（親指）テスト**： 仮判定・合格。タッチターゲットは全て不変（タブ 56dp、セグメント／チップ 48dp 以上、折りたたみ見出しは全面タップ可）。危険な操作は存在しない。
- **折りたたみテスト**： 仮判定・合格（見出し「くわしい数値」は不変）。
- **到達確認**： 今回は情報の移動・折りたたみ化をしていないため対象なし（表示の定数と整列のみの変更）。
- **アクセシビリティ確認（静的）**： アイコンの contentDescription は全て不変（詳細の気圧見出しも「気圧」のまま）。コントラストは上記の再走査で全ゲート合格。動きを減らす設定・省電力では空が静止画になる仕様は不変で、新定数は静止画でも同じ値が効く。文字拡大時のレイアウトは実機未確認。

## 実機でしか分からない点（正直に）

- **空の動きとカードの競合の実感**： 雲・雨・霧を弱めた量（α で約2割、雨の速さで約24%）が「ちょうど静かになった」のか「まだうるさい」のか「弱めすぎて空が死んだ」のかは、数値でもコードでも判定できない。特に雨の日のホームと、霧の日のカードの背後が要確認。
- 太陽／月の弧を上げたことで、天体がステータスバー寄りに窮屈に見えないか。
- アイコンの上端揃えが、補足文の長い服装カードで「アイコンの下が空いて間延び」して見えないか（中央揃えとの好みは実物でしか比べられない）。
- 統計アイコン 16dp の見え方（14dp との差が実機で意味を持つか）。
- 静止画モード（動きを減らす設定）での空の見え方 — 定数は共通だが未確認。
