# FEATURE v0.1.41 — 空のシーンは、端末設定でなく時間と天気で決める

- 版： versionName 0.1.41／versionCode 42
- 日付： 2026-11-28

## 発端（本人の実機スクショと決定）

2026-11-28 14:29、本人が実機で開いた画面のスクショを送ってきた。端末はダークモード、時刻は昼の 14:29、天気は雨。ところが画面全体が濃紺の「真夜中」の見た目で、雨の日の昼とは思えない絵になっていた。あわせて右上に、正体のはっきりしない灰色の丸が見えた。

原因は、空のライト／ダークのパレット選択が端末のダークモード設定（uiMode）に追随していたこと。ダークモードの端末では、昼でも夜のパレットで描いていた。右上の灰色の丸は、その夜パレットで描かれた太陽だった（太陽の芯 #E8A34F を α20、グロー α24 で夜空に置くため、淡い灰色の円盤に見えていた）。

本人の決定（選択肢ボタン、2026-11-28）： **「空は時間と天気で決めるよう直す」**。本書はその実装記録。

## 設計 — 「シーン」という考え方

ライトな空＋濃紺文字と、ダークな空＋淡い文字は、端末設定の2値ではなく、**その地点のいまの空が持つ1つの連続量**として扱う。

- **sceneDark（sd）** = `1 − smoothstep(0.10, 0.55, dayness)`。dayness は従来の位相式（日の出 −40分〜+50分で立ち上がり、日の入り −50分〜+40分で落ちる）のまま。sd は昼に 0、夜に 1、夜明け・夕方にその間を連続的に通る。日の出・日の入りはその日の予報の値を使う（予報が無いときは従来の既定 6:00／18:00）。
- **空のグラデーション**： 両シーンのストップを従来の式（位相混合＋天気キャスト）でそれぞれ計算し、sd で混合する。下のストップほど先行して暗くなるよう整形する（top = sd、mid = min(1, sd×1.06)、bot = min(1, sd×1.12)）。夕方の地面側から暮れていく見え方であり、後述の再走査で最も厳しかった「夜明けのダークガラス×下端ストップ」を通すための形でもある。sd が 0／1 の端点では、v0.1.40 のライト／ダークの絵と完全一致する。
- **環境グロー**： 色と α の両方を sd で混合する。
- **SkyView の要素**： 太陽・月・雲・霧・雨・雪の色と α を sd で連続混合し、星は sd に比例して現れる（sd > 0.02 で描画開始、α に sd を乗算）。昼の端点・夜の端点の値は従来どおり。太陽と月は両シーンで同じ弧の上にあり、sd で姿が入れ替わる（太陽の芯 #FFD76A α235 → #E8A34F α20、月の芯 #F4F8FB α110 → #9FB8CC α30 等）。これにより「右上の灰色の丸」は解消した： 昼はライトシーンの太陽として正しく描かれ、夜は月になる。
- **夜の雨の色**： ダーク側の雨筋の色を #5B7A94（濃い灰青）から **#CFE4F2（淡い水色）** へ変更した。α は従来どおり 82。暗い空でも雨筋が沈まないための変更で、再現スクリーンショット（後述）で視認を確認した。ライト側の雨（#5B7A94 α92）は不変。
- **UI トークンのフリップ**： ink／sub／paper／accent／ガラスの色は連続混合しない（中間色の文字はどちらの地でもゲートを割ることを走査で実測したため）。**sd ≥ 0.90 で一回だけ**切り替える。この深い位置で両側が通る根拠は次の2つ。
  - **小文字用ハロー（新設）**： 空の上に直置きされる小さい文字すべて（ヘッダーの地点名・「明日」ラベル・「今日を見る」、注記行3種、smallLine、詳細の地点名、セクション見出し・説明、設定フッター、エラー／読み込みの文言）に、半径 8dp のハロー（色は結論のハローと同じ、α230）を敷いた。走査モデルでは係数 0.65（結論の 16dp ハローは 0.45 のまま、ゲート 3.0）。
  - **ガラスの移行帯増厚**： ライト側の読み物ガラスの fill α を、sd ∈ [0.45, 0.90] の範囲で連続的に最大 1.32 倍まで増厚する（薄側 138→182、厚側 158→約208）。sd = 0 では Simple Glass 正本値そのまま。ダーク側（48→33）は不変。
- **ステータスバー**： アイコンの明暗（APPEARANCE_LIGHT_STATUS_BARS）はトークン側（sd ≥ 0.90 でダーク側）に追随する。
- **追随範囲**： ホーム・詳細・設定・エラー・読み込みの全画面が同じシーン決定に従う。背景にいる間に夕方を跨いだ場合は、復帰時（onResume）にトークン側が変わっていれば現在の画面を再構築する。端末のダークモード切替では何も変わらない（onConfigurationChanged は何もしないことが仕様）。ウィジェットは従来の4面（時間・天気で決定済み）のまま変更なし。

## コントラスト再走査

方法： 到達可能な全状態を、日の長さ3種（日の出／日の入り = 5:00／19:00、6:00／18:10、7:00／17:00）× 1分刻み × 天気グループ7種 × shade {最大, 半分} で走査し、実在する全ペア（文字×地の組合せ）を WCAG コントラスト比で判定した。地のモデルは v0.1.38 の走査と同系（ストップ色への α 合成、ガラスは面の色＋α、ハローは係数モデル）。

結果： **実在する全ペア合格**。最弱値：

| ペア | 最弱値 | ゲート |
|---|---|---|
| ink × 地点チップ（stop2） | 4.62 | 4.5 |
| sub × 小文字ハロー（係数 0.65、stop2） | 4.96 | 4.5 |
| sub × 読み物ガラス（stop2） | 5.15 | 4.5 |
| ink × 読み物ガラス | 6.63 | 4.5 |
| onAccent × accent | 7.85 | 4.5 |
| 結論（ハロー係数 0.45） | 4.67 | 3.0 |

注記（地モデルの差異）： v0.1.38 の記録にある「ダーク・夜明けのガラス上の補助文字 4.19」は、あちらのより厳しい地モデルでの値。本走査のモデルでは定常ダーク状態で約 4.98 になる。モデル差があるため絶対値の単純比較はできないが、本走査は移行帯を含む全到達範囲で 4.5 を割らないことを確認した、というのが本版の主張である。

なお sub × 地点チップ（3.59〜3.70）という組合せは走査上現れるが、地点チップの文字は ink で描かれ、sub は枠線のみに使われるため、文字ペアとしては実在しない（対象外）。
