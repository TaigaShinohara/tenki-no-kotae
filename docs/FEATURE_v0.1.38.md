# FEATURE v0.1.38 — 空が天気と時間で変わる

本人の指示（2026-11-27）：「今の雰囲気を保ったまま天気や時間に
合わせて変わるようにして」。v0.1.37 の A案「そらグラデーション」
の世界観（空グラデ背景＋濃紺テキスト直置き＋白の読み物ガラス
カード＋浮いたピル型タブバー）はそのままに、空のパレットが
**天気グループ × 時間帯フェーズ** で変化するようになった。

## 仕組み：天気キャスト

- 位相（夜明け／昼／夕方／夜）は従来どおり `daynessAt`／`warmAt`
  （日の出・日の入り基準）が担う。v0.1.38 はその後段に
  **天気キャスト** を追加： いまの時間帯の天気コードから決まる
  7グループ（晴れ／晴れ時々曇り／曇り／雨／雪／雷／霧）ごとに、
  3ストップそれぞれをアンカー色へ（ストップ別比率 × shade）
  引く。対応表 `SkyView.skyGroupForCode` はアプリとウィジェット
  で共有する1実装（WMO コード、予備源 MET Norway のシンボルも
  同コードへ写像済みなので両源で同じ空になる）。
- shade は天気コードの行ごとに固定（`skyWeather` の表）：
  晴れ 0、晴れ時々曇り 0.45／0.7、曇り 0.85、雨 0.5〜1.0、
  雪 0.65／0.8、雷 0.85／1.0、霧 0.75。**晴れ（shade 0）は
  v0.1.37 の色と完全に同一**（キャストなし）。
- アンカー（ライト）： 晴れ時々曇り #B0C2D4（.26/.24/.28）／
  曇り #A9BACA（.30/.34/.44）／雨 #A5B6C6（.30/.36/.55）／
  雷 #9FB2C4（.34/.38/.52）／雪 #E8EEF4（.36/.40/.34）／
  霧 #B2C1CC（.46/.48/.50）。ライトの湿りアンカーは「暗く」
  ではなく「脱飽和」に寄せた（曇りの昼空は明るい灰色であり、
  夜の上端ストップは補助文字の最弱地 4.58:1 でもあるため、
  実際に暗くするとゲートを割る——走査で確認済み。沈んだ
  印象は地平線の桃色の消失・雲の暗さ・雨筋が担う）。
- アンカー（ダーク）： 晴れ時々曇り #0F1B2A（.20/.18/.16）／
  曇り #0E1926（.32/.30/.27）／雨 #0B141F（.46/.43/.40）／
  雷 #060C14（.52/.50/.46）／雪 #2B3D54（.26/.26/.24、月明かりの
  雪面として僅かに持ち上げる）／霧 #1A2634（.42/.40/.38）。
- **環境グロー**は shade で薄める（α × (1 − 0.5 × shade)）：
  曇天・雨天で結論の背後に陽だまりが残らない。晴れは従来の
  強さ（ライト α170／ダーク α110）のまま。
- 雲の量・暗さ、雨筋、雪、霧の帯、星、太陽・月の弧は従来
  （v0.1.9／v0.1.10）の連動のまま。雷は稲妻を描かず、最も
  深いキャスト＋暗い雲＋雨で示す（モーション規律どおり）。
- 空は従来どおり「いま」の天気・時刻を映す（v0.1.36 の決定：
  夜間・明日表示でも空は今日／いま）。詳細・設定も同じ
  SkyView の地の上で従来どおり追随する（固定の空色パーツ
  ——セグメントのコンテナ、チャート面塗り——は不変）。

## ウィジェットも空に追随

- スナップショットに「現在の天気コード」と「日の出／日の入り
  （分）」を追加保存（新しい取得はなし。ホーム表示時の保存に
  相乗り）。面は4種から選択（`TenkiWidgetProvider.faceFor`）：
  - **昼**（日の出〜日の入り、湿りなし）： アプリのライト空
    そのもの #8FB4E6 → #C2DCF5 → #FDEBCB、縁 #7FA8E0。
    文字は濃紺（本文 #1E2C5F／補助 #2E3C72）。
  - **湿った昼**（雨・雪・雷・霧）： 灰青 #A3B4C5 → #B9C9D6 →
    #CDD4CE、縁 #8299AE。文字は濃紺。
  - **夜**： v0.1.37 の夜空グラデーション（不変）。
  - **湿った夜**： 沈んだ灰紺 #131E2A → #1D2B3A → #2A3138、
    縁 #43536A。文字は夜の淡色のまま（地が暗くなり余裕が増える）。
- 見出しの「その日の色」（accentDark）は **夜の2面でのみ**
  存置。ライト側の色は昼空の上端で最大 4.04:1 とゲート未達
  のため、昼の面の見出しは濃紺にした（走査結果に基づく判断）。
- 旧版のスナップショット（空の項目なし）は既定値（コード
  なし・06:00/18:00）で夜の面になり、次のホーム表示で
  更新される。面の切替はスナップショット保存時と OS の
  30分定期更新のタイミング（再描画のみ・取得なし）。

## 変えていないもの

- ホームの構造（B5、固定高・スクロールなし）、全ロジック・
  判定ルール、夜間明日モード（19時）、データ取得、

## コントラスト再走査（WCAG、実装値そのまま）

到達可能な（dayness, warm）の組を、3つの日の長さ（日の出
5:00／6:00／7:00）で5分刻みにサンプリングする厳密モデルで、
全グループ×（shade 半分／最大）を走査。合格条件は
**「全ペアで晴れ（= v0.1.37 出荷パレット）のベースラインを
下回らない」** とし、全グループ合格した。

## テスト

- 全144件中143件合格（`tools/run-unit-tests.sh verify`、
  フルスイート。従来137件＋新規7件： SkyGroupTest 3件
  （コード→グループ対応、ウィジェットの面選択）、画面
  ゴールデン新規4枚（home_cloudy／home_rain／home_snow／
  home_dusk））。新規・既存の画面ゴールデンはフルスイート
  文脈での再記録で確定した（v0.1.37 の教訓どおり。あわせて
  home.png／detail.png も同セッションで再記録されている）。
- 残る1件の失敗は既存テスト home_nightShowsTomorrow
  （夜間明日モードのラベル確認）で、**実時刻依存**：
  この VM の直接 JUnitCore 実行では Robolectric の壁時計
  ピンが効かず（setCurrentTimeMillis が true を返しても
  System.currentTimeMillis が実時刻のまま——切り分け用の
  使い捨てテストで実測）、このテストは実時刻が 19:00 を
  回った状態でしか通らない。v0.1.37 の検証は夕方（21時台）
  に行われたため合格していた。今回の実施は未明（1〜2時台）
  で、アプリ側・v0.1.38 の変更とは無関係に落ちる。
  ゴールデン側も同じ理由で「記録と検証を同じ時間帯の
  セッションで行う」前提が元々ある（v0.1.37 の記録も
  夕方の状態で焼かれていた）。実際、別時刻の再検証では
  detail.png が実時刻の「時」の境界をまたいで 1件追加で
  落ちた（142/144）——「いまから」の表示窓が実時計の
  時間で決まるためで、これも既存の性質。
- バリエーションの顔ぶれ： 晴れ・昼＝home.png、夜＝
  home_night.png（晴れの夜）に、曇り・雨・雪・夕方を
  新規追加し6種が揃った。空の位相は SkyView の
  clockMillis 上書きで固定されるため、この4枚は
  実時刻に依らず再現する。
- フィクスチャは ScreenshotSupport の天気別キャッシュ
  （曇り＝コード3、雨＝コード63、雪＝コード73、夕方＝
  晴れフィクスチャ＋17:50 ピン）。

## 残った課題（実機待ち行列）

- 天気キャストの空気感（雨の沈み具合、雪の白さ、夕方の
  橙の寄り方、ダークでの見え方）は数値ゲートでは測れない。
  実機スクショでの見え方確認は本人のタイミング待ち。
- 雪の日に雨筋も薄く混ざる（降水量フォールバックが雪
  コードでも雨筋を出す既存仕様。v0.1.38 では変更して
  いない。home_snow.png で確認できる）。
- テスト基盤の実時刻依存（上記「テスト」節）： 夜間
  テストと既存ゴールデンは、記録・検証の実時刻帯に
  依存する既存の性質。恒常対策（テスト側の時計固定の
  実効化）は本版の範囲外として残す。
- 検証環境の注意： 実施時、この VM の共有ビルドロックに
  他プロジェクトのビルドが多数並び、テスト・ビルドの
  開始まで長時間待った（ロック競合による待機であり、
  ビルド自体の失敗ではない）。
- ウィジェットのプレビュー模式図（widget_preview.png）は
  旧来のまま（実表示は4面で描画される）。
