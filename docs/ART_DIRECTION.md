## 0. アプリ全体の意味（3点）

- 一番見せたいもの： 今日の結論の一文。
- どう思ってほしいか： 「もう考えなくていい、任せた」。
- 主な手段： 結論を最大の文字＋その日の色で画面最上部に置く。残りは全部、結論の従者として静かに並べる。

## 1. 世界の言葉

- 雰囲気キーワード（3つ）： **朝の光**／**静か**／**明るい**。
- 朝、玄関で開くアプリ。夜更けのダッシュボードでも、役所の掲示板でもない。
- やらない雰囲気：
  - 数値とグラフが主役の「気象データ端末」風（コンセプトの敵）。
  - 色の洪水（1画面に何色もベタで使う）。色はその日の1色だけ。
  - 派手なグラデーション、虹色、原色の光。光はその日の色の淡色だけ。
  - 警告色で脅す表現。安全帯（設計 §2）だけは例外だが、通常画面に赤は持ち込まない。

## 2. 色の性格 — 「その日の色」は1色だけ

### 決め方

- 画面のアクセント色は **その日の色** 1色のみ。その日の色は **今日の日中平均体感温度**（Rules.daytimeAvg、9〜18時）で決まる。
- 理由： 開いた瞬間に、文字を読まなくても「今日は寒い日／暑い日」が色で分かる。色そのものが答えの一部になる（minimal_information_design 原則3：色と状態の変化で示す）。
- その日の色の使い道は3つだけ： ①結論の文字色 ②カードのチップと見出しラベル ③選択中タブ・主ボタンのベタ。面積比は 地（紙＋ガラス）約7割／淡色ティント約2割／役割色ベタ約1割（Simple Glass quality §2）。
- データ未取得時（読み込み・エラー）は「空」の色（ライト #0277BD／ダーク #7CC7F0）を仮の色とする。

## 3. 質感 — Simple Glass 正本（v0.1.4 で全面採用、素の View への適応）

- カード等の「文字が乗る面」は **読み物ガラス** を既定とする。小さい文字の面（チップ・選択中タブ・主ボタン）はベタ。
- 土台は Simple Glass 標準の土台（quality.md §1）とする：
  - グラデーション3点（上→下・同系色のみ）： ライト＝ ティントに白30%混ぜ → ティント → 紙。ダーク＝ **ティントを紙へ25%寄せ** → ティントと紙の中間 → 紙（v0.1.6 で変更。旧「ダークの上端はティントそのまま」では、ティント色の主光が同色の地に溶けて実機で見えなかった。ラベルは v0.1.5 からベタのピル上にあり、上端を深めてもゲートは再走査で全帯合格）。
  - 光は3つ（quality §1 テンプレ： 主・副・中央下）。ライトは従来どおり（左上に主、ティントのみ、直径 350／320／300dp）。**ダークは v0.1.6 で再構成**： 主光は結論の背後（画面の 0.30w, 0.17h）に置き、色はティントを白へ22%寄せ、アルファ 225、半径 230dp。副（右下）はティントのままアルファ 225・半径 190dp、3つ目（中央下）はティントのままアルファ 200・半径 180dp。画面端からはみ出させる。素の View にはぼかしが無いため、光は放射グラデーションで描き、縁が完全に溶ける形で「ぼかし約70dp」の代替とする。
  - 土台は全画面共通1種（v0.1.8 までは BaseBackground。v0.1.9 で「生きている空」SkyView に置換 — §3 の v0.1.9 追記）。画面ごとに作らない。
- 面（読み物ガラス）： **v0.1.6 から「色付きガラス」**。面の色は白ではなくその日のティントそのもの（スキル規定「色付きの面はブランド色の淡色をそのまま使い、透過で馴染ませる」）。上→下のやんわりグラデーション： ライト＝ ティントを白へ30%寄せ @82% → ティント @73%。ダーク＝ ティントを白へ10%寄せ @69% → ティント @59%。旧値（ライト＝白 62%→54%、ダーク＝白 19%→13%）はダークで無色の灰色に濁り、実機で「コンクリートの板」に見えたため廃止（v0.1.6 追記）。
- ふち（スペキュラハイライト）： 1dp のリングをグラデーションで描く。上＝白 75% → 下＝白 15%（ダーク 38% → 6%）。v0.1.2 の「全周一様ストローク」の代用は廃止し、正本どおり上下差のある縁にした。
- backdrop blur は素の View に無い。スキルの規定（backdrop-filter が効かない環境では、読み物ガラス以上は背景色だけでも分離する濃さを維持する）どおり、面の濃さで分離を担保する。API 31+ の RenderEffect は採用しない（API 分岐で見た目が割れるのを避け、全 API で同じ放射グラデの光に統一するため）。
- 役割色ベタ（選択中タブ・主ボタン）は、上に白8%混ぜ→下に黒4%混ぜのやんわりグラデーション。文字色はベタの輝度で決める： 暗いベタ（ライト側の全帯）には白、明るいベタ（ダーク側の全帯＝淡色アクセント）には本文色。コントラスト 4.5:1 を割らないための必須ルール（v0.1.2 の自己点検で検出・明文化）。
- 状態（quality.md §3）： 主ボタン・選択中タブは押下＝深いグラデ（白+2%→黒−10%）、フォーカス＝通常グラデ＋濃い縁で定義する。未選択タブ・ラジオ行は押下で薄い白面が出る。ラジオは未選択＝ガラス色のリング、選択＝アクセントベタ＋マーク（色＋形の両方で示す）。

### v0.1.6 追記（実機フィードバック「ダサい」への対処）

本人が v0.1.5 を実機（ダークモード）で開き、「ダサい」と評価した。スクショから読み取れた問題5点と対処：

1. **カードが灰色の板に見える（最大の問題）**： 白 19→13% の透過を暗い背景に重ねると色相が消え、無色のグレーに濁った。「その日の色」が面に入っていなかった。→ 面を **色付きガラス** に変更（§3 の面の項）。変更前＝白アルファ一辺倒、変更後＝その日のティントを面の色として透過させる（ライト： ティント白+30% @82% → ティント @73%／ダーク： ティント白+10% @69% → ティント @59%）。モデル上の面色（ダーク・寒い帯・画面中央）は RGB(70,74,78) の灰色 → RGB(36,53,66) の深い青に変わる。
2. **見出しピルの二重表記**： 「服 服装」「傘 傘」「日 日焼け止め」と漢字1字＋同義ラベルが並んで間抜けに見えた。→ ピルは **ラベルのみ**（「服装」「傘」「日焼け止め」「気圧」）にし、漢字1字の記号は廃止（§4）。あわせてダークのピル面は、カード面自体がティント色になったため、ティントを黒へ 28%→38% 寄せた「濃いティント」に変えて面と分離した（アクセント文字との最弱値は 8.09:1 に改善）。
3. **地点名「大阪」がステータスバーに食い込む**： targetSdk 35 の edge-to-edge でコンテンツがステータスバーの下に潜り、時刻表示と重なって潰れていた。→ ルートに WindowInsets のリスナーを付け、システムバーのインセットをパディングとして適用（背景は全面に描いたまま、子だけを内側へ）。全画面（ホーム／詳細／設定／読み込み／エラー）共通の土台で処理する。
4. **背景の「光」が実機で見えない**： ダークでは土台上端＝ティントそのものだったため、ティント色の主光が同色の地と同化していた。→ 土台上端を紙へ25%寄せて深くし、主光を結論の背後（0.30w, 0.17h）に配置、ティントを白へ22%寄せ・アルファ 225・半径 230dp に強化（§3 の土台の項）。モデル上、結論中心の地の明るさは輝度 0.020 → 0.069（RGB (25,41,53) → (60,76,89)）になり、光として視認できる差になった。
5. **全体の締まりのなさ（結論の水色だけが浮く）**： 周りが灰色だったための症状。1 の色付きガラス化でカード・タブバー・ピルまで同じ色相でつながるため、結果として解消する想定。最終判定は実機のみ。

**教訓（恒常ルールとして記録）**：
- **コントラスト等の数値ゲートは「読めるか」しか測れず、「見た目が良いか」は測れない。** v0.1.4／v0.1.5 はゲート全合格でも実機ではダサかった。数値検証は必要条件であって十分条件ではない — 以後は実機スクショでの見た目確認を前提に設計し、ゲート合格をもって「良いデザイン」とは報告しない。

- **光は地と同色では存在しないのと同じ。** 光を置く場所の地の色と、光の色に明度差を設計すること。
- 再走査（全7帯×明暗×全配置、160チェック）： 全ゲート合格。ダークの最弱値＝ 結論（大きな文字）3.82（ゲート 3.0）、ガラス上の補助 5.66、ガラス上の本文 7.75、ピルのアクセント 8.09、ヘッダー補助 5.48。ライトの最弱値は従来どおりピル 4.60／ベタ上の文字 4.56（不変のパーツ）。

### v0.1.9 追記（生きている空 — 土台の置き換え）

本人の指示で、土台は静止画であることをやめ、「その地点のいまの空」そのものになった。実装は SkyView（カスタム View＋Canvas）。駆動データは既存の取得済みデータだけ（今日の天気コード・降水・日の出／日没＋現在時刻）で、新しい取得は追加していない。

- **空の色（位相グラデーション）**： 3点グラデの素地は従来の土台と同じ（ライト＝ティント白+30% → ティント → 紙／ダーク＝ティントを紙へ25% → 45% → 紙）。ここに時刻の位相を重ねる。dayness（0=夜〜1=昼、日の出 −40分〜+50分 と 日没 −50分〜+40分 の smoothstep の積）で、ライトは夜スレート #8EA6BE へ（上 0.42／中は紙と混ぜた夜スレートへ 0.34 の割合で (1−dayness) に連動）、ダークは昼の明るさ #35526B へ（上 0.42／中 0.34／下 0.12 の割合で dayness に連動）。warm（日の出+15分・日没−15分を中心とする幅60分のガウス）は朝夕の橙みで、ライト #FFC99A（上 0.32／中 0.26／下 0.12）、ダーク #8A5A38（上 0.18／中 0.16／下 0.08）。ステータスバーの地色は空の上端に一致させる。
- **環境グロー**： 旧・主光（結論の背後 0.30w, 0.17h、半径 230dp）は空の環境光として存置。ライト＝ティント α200／ダーク＝ティント白+22% α225。副光・3つ目の光は空の要素（太陽・月・雲）に役割を譲り廃止した。
- **太陽／月**： 上部右の弧（x 0.56w〜0.92w、高さは sin カーブで最大 0.105h 上昇）を、日の出〜日没（太陽）／日没〜日の出（月）で進む。可視度は dayness の smoothstep と曇り具合（1 − 雲量×0.75）で決まる。ライトの太陽はグロー #FFE9B0 α150（半径 110dp）＋芯 #FFD76A α235（半径 16dp）。**ダークの太陽・月は意図的に淡いグローに留める**（グロー α24／芯 α20、月 α20／円盤 α30）： 明るい円盤が結論の背後に来ると大きな文字の 3:1 ゲートを割るためで、「ゲートが絵に勝つ」判断として記録する。
- **雲**： 7個の雲プール（各5つの放射グラデ blob）。天気コードから決まる雲量で目覚める数が変わり（wake = 雲量×7 − 順位）、暗さ（cloudDark）で色が変わる（ライト＝白→ #A9BFD2／ダーク＝ #46586A → #3E4C5A）。blob のピーク α はライト 96／ダーク 34。流れは左→右へ数分で横断する速さ。
- **雨・雪・霧・星**： 雨は斜めの細い筋（雨レベル 1〜3 で 30／60／90 本、α ライト 115／ダーク 100）。雪は 60 個の遅い粉雪（横揺れつき）。霧は横帯 3 本の潰れた放射グラデ（α ライト 60／ダーク 26）。星はダークのみ 70 個（月の可視度と雲量で出現）。雷は稲妻を描かず、暗い雲＋強い雨で表す（点滅禁止、§6）。
- **天気への対応（WMO コード、予備源も同じコード空間）**： 0=快晴（雲 0.06）／1=晴れ（0.25）／2=薄曇り（0.5）／3=曇り（0.85、暗 0.35）／45・48=霧／51〜57・61=雨1／63・66・67・81=雨2／65・82・96・99=雨3／71〜77・85・86=雪／95=雨2・暗 0.7。降水量の補正： コードが雨でなくても降水 0.1mm 以上なら雨1、雨の日に 2.0mm 以上なら雨3。
- **データが無い時**（読み込み・エラー）： 天気要素なし、時刻だけから空を出す。仮の色（空色）の帯で位相だけが移ろう。
- **コントラスト再走査（確定の根拠）**： 空の式・天体・雲の全定数を、7帯×明暗×位相格子（dayness 5段×warm 3段）×全配置で数値走査した。最悪条件として「グリフがグローの中心に重なる」「雲が2枚重なる」を含む。結果 **6,944 チェック全合格**： 4.5 ゲートの最弱 4.58（ライト・寒い帯のベタ上文字、v0.1.5 から既知の律速）、3.0 ゲートの最弱 3.09（ダーク・あたたかい帯、dayness=1 かつ warm=1 という物理的に到達しない組合せでの太陽グロー）。空の定数を変えるときは必ず再走査すること。雨・雪・星・霧は細線・小要素として走査対象外（霧の色・α は本文ゲートに影響しない淡さに固定）。
- **教訓の継承**： 数値ゲートは「読めるか」しか測れない（v0.1.6 の教訓は空にも適用される）。空の実際の見え方・にぎやかさの加減は実機スクショでの確認事項として残す。

## 4. 形の言語

- 角丸トークン： カード 24dp／タブバー土台 24dp／ボタン・チップ・選択中タブは全丸（高さの半分）。これ以外は使わない。
- アイコン的記号： 絵文字は使わない。カードの種類は **チップピル（ラベルのみ）**（服装・傘・日焼け止め・気圧）で示す。ピルはその日のティント系のベタ面（ライトは §3 追記の薄めた面、ダークはティントを黒へ28%→38%寄せた濃いティント＝ v0.1.6）、文字はその日のアクセント。（v0.1.4 までは丸チップ（円）＋ガラス上のラベル、v0.1.5 で漢字1字＋ラベルのピル型に統合したが、実機で「服 服装」の二重表記が間抜けに見えたため v0.1.6 でラベルのみにした。）
- **線画アイコン体系（v0.1.9 で新設、Icons.kt が実装の正）**： 答えの「絵」をコード描画のベクター線画で統一する。規格は1系統のみ — 24 ユニットのボックス、ストローク 2.1 ユニット、丸キャップ／丸ジョイント、単色（置かれる文脈の ink または補助色）。外部素材・画像ファイルは使わない。絵柄は意味が一般に固定したものだけを使う（服の形、傘の開閉と斜線、ボトル、波線＋下降矢印、月／太陽、ピン、温度計、上下矢印）。全アイコンに読み上げ名（contentDescription）を必ず付ける。
  - **アイコンは文字の複写ではなく「絵」**： 漢字1字を置くことはしない（v0.1.6 の二重表記の失敗）。アイコンは「読む前に形で届く」先行表示であり、Rules の答えの文章は置き換えず、そのまま残す。
  - **ラベル併用の原則**（minimal_information_design）： アイコン単独で意味が固定しないものは短いラベルを併用するのが正解。行動カードはピルラベル（種類）＋アイコン（今日の状態の形）＋文章（答え）の3層で、アイコンは状態の違い（傘が開いている／畳んである／斜線、服の厚み、気圧の落ち方）を受け持つ。詳細・設定の小アイコンは見出しの添えであり、ラベル文字列は常に併記する。
  - 置き場： 行動カードの本体行の先頭（38dp）、帰り／明日の行（20dp）、詳細のヒーローラベル・統計ラベル・気圧見出し（18／14dp、補助色）、設定のセクション見出し（20dp）。新規アイコンは UI_CATALOG に登録してから使う。
  - **今日の人（v0.1.14 で追加、v0.1.15 で線画を描き直し、v0.1.16 で生成画像へ、v0.1.19 でレイヤー合成へ）**： アイコン体系の延長ではなく独立した「場面の絵」。キャラクターは本人が確定した見た目（雲のような濃紺のもこもこ髪・淡い水色の肌・中性的な顔立ち）で不変。v0.1.19 からは本人の指示で **パーツのレイヤー合成**： 素体3種（body_a／b／c）＋トップス6種を共通キャンバス（1120×2240）の bbox で位置合わせし（PersonCanvas、カーディガンとニットコートは着丈の較正あり）、小物（キャップ／ニット帽／マスク／サングラス／マフラー／首タオル／ミトン／傘／日傘／うちわ／折りたたみ傘）は素体ごとのリグ（顔の箱・両手、PersonRigs）から PersonAnchors の比率で重ねる。ランク5だけは従来の全身イラストを土台に新パーツを重ねるハイブリッド（冬コート素材の比率が素体に合わないため）、レインコートは全身差し替え。汗・震えの記号は v0.1.19 でコード描画に戻した（全身画像への焼き込みは廃止）。線画アイコン体系（Icons.kt）とは別系統であり、体系の「外部素材・画像ファイルは使わない」はアイコン側の規格として残る（今日の人だけが例外）。描き分けの決定は従来どおり純粋関数 `PersonFigure.spec`（服装ランク／傘／UV帽子の閾値は v0.1.14 から不変、v0.1.19 で雪・日中平均体感・日中平均湿度の入力と新ルールを追加）。単独の記号ではなく場面の絵なので、ラベル併用の原則の対象外（代わりに contentDescription に服装の答えを入れる）。置き場は画面の水平中央で、縦は結論とチップ列の間の空きスペースの中央（v0.1.15 で結論直下の右端、v0.1.17 で本人の指示により水平中央へ、v0.1.18 で縦も中央へ）。大きさは v0.1.18 から残り高さ比例（60%、150〜230dp）で、標準画面で約 200dp、最小画面で約 150〜170dp。v0.1.19 で日傘・ニット帽の頭上パッド（padTopRatio）も高さの予算に含めた。詳細は `docs/FEATURE_v0.1.19.md`（v0.1.16 のアセット合成の記録は `docs/FEATURE_v0.1.16.md`）。
- 線： 区切り線は使わない。要素の区切りは余白と面で行う。

## 5. 文字と密度

- 書体は端末既定の1系統のみ。太さは通常／太字の2種。
- サイズ階層は4段（トークン）。本文段だけ、置かれる面に応じて2値を許す：
  - 結論： （v0.1.13 でエディトリアル段へ、v0.1.17 で実測フィットへ）太字、行間 1.22。サイズは文字数の段ではなく実測で決める： 各文が表示幅（画面幅−左右余白40dp、2%の安全マージン付き）に1行で収まるサイズを測り、2文の小さい方に統一する（上限 46sp／下限 24sp）。下限でも収まらない文は文節の区切りで1回だけ改行し、結論全体は最大3行（両文とも最長級の組合せでは改行せず下限未満のフィットで2行を守る）。基本形は「1文＝1行・全体2行」。空の上に直置きするため、文字にはハロー（ライト＝白 α230／ダーク＝ rgb(8,11,16) α230、半径16dp、オフセットなし）を敷く — これは面の影ではなく文字の下地で、§3 の「面に影を付けない」とは別物。大きな文字ゲート 3:1 は再走査で全組合せ合格（最弱はライト・寒い帯＋雲重なりで 3.75）。ライトで 4.5 に届かないのはアクセント #0277BD の物理的上限（どんな明るい面でも約4.65）のためで、色は変えない（判断の記録は `docs/LAYOUT_v0.1.13.md`）。詳細の体感ヒーローは従来どおり 34sp を流用
  - 見出し： 20sp 太字（カードの主文、結論の補足行）。画面タイトルは置かない（v0.1.7： 下部タブが画面名を常時示すため、重複として廃止）
  - 本文： 16sp、行間 1.6（カード内の補足文は 14sp、行間 1.6）
  - 補助： 13sp、行間 1.6（ラベルは 13sp 太字）
  - グラフ内蔵の文字（v0.1.8）： 詳細のグラフに描く値ラベル・時刻ラベルは補助段（13sp）相当で描く。新規のサイズ段は作らない。体感ヒーローは結論段（34sp）、気圧の現在値は見出し段（20sp）を流用する
- 余白スケールは 4／8／12／16／24／32 のみ。画面の左右 20dp、上 24dp（結論の前は 32dp 空ける）、カード内 左右20・上下16、カード間 12、セクション間 24。
- タッチターゲット： タブ 56dp、ラジオ行・ボタンは最小 48dp。

## 6. 動きの性格

- 意味を書けない動きは入れない。
- 段階表示は v0.1.7 でホームに実装した（minimal_information_design 原則6）： 新しいデータの表示時に限り、結論 → 行動カード → 帰り・明日の順にフェード＋8dp 上昇（開始 50ms・間隔 70ms・各 220ms、全体で約0.9秒以内）。（v0.1.13： ホームの構成変更に合わせて対象は 結論ブロック → 答えチップ列 → 小行群 の3グループになった。速さと条件は不変。）タブ切替では再生しない（行き先が分かっている繰り返し操作を待たせない）。システムのアニメーション無効設定では即時表示し、最終状態だけで情報が完全に伝わる形にする。詳細は `docs/INFO_REVIEW_v0.1.7.md`。
- **空のアニメーション規律（v0.1.9）**： 背景の空は常時アニメーションだが、「朝、玄関で3秒」のトーンを守る — 雲は数分で画面を横断する速さ、雨・雪は静かに落ち、太陽／月の移動は開いている間には知覚できないほど遅い。点滅・明滅は一切しない（雷も稲妻では表さない）。フレームループは約30fpsに制限し、Activity が見えている間（onResume〜onPause）だけ回す。OS の「動きを減らす」設定（アニメーター無効／duration scale 0）または省電力モードでは、その状態の空の静止画にする。静止画でも天気と時刻は色と要素の配置で完全に伝わること（動きは情報の担い手にしない）。

## 7. 画面ごとの意味

| 画面 | 主役 | どう思ってほしいか | 手段 |
|---|---|---|---|
| ホーム | 結論1文 | もう考えなくていい、任せた | 空の上に特大文字＋その日の色＋大きな余白（v0.1.13 エディトリアル形： カードなし、答えは下部のチップ列、残りは小行。全文の答えは詳細の「今日の答え」へ）。v0.1.14 で「今日の人」が加わり、出かけ方が絵でも届く（v0.1.15 で結論ブロック直下へ寄せ、v0.1.17 で画面の水平中央に置き、v0.1.18 で結論とチップの間の空間の中央に浮かせて大きくした（残り高さの60%）。結論が主役であることは不変） |
| 詳細（数値で見る） | （主役なし）答えの裏付け | 必要な時だけ静かに確かめられる | 要点は数字と形で（体感ヒーロー＋折れ線/バーのグラフ、気圧は現在値＋スパークライン＋1行）、全数値と時間別表は「くわしい数値」に折りたたむ（v0.1.8）。色は使わず無彩色で統一（面とグラフの面塗りはその日のティント） |
| 設定 | （主役なし）自分の感覚の申告 | 選べば提案が自分に寄る、と分かる | 選択はセグメントとチップで「操作の形」にする（v0.1.8、ラジオは廃止）。変わる項目（体感・感度）にだけ、両端の変化を言う1行の説明を添える。自明な項目（地点）には付けない（v0.1.7） |
| 読み込み中 | 「取りにいっている」こと | すぐ答えが来る | コンセプトの言葉＋その日の色（空色）のプログレス |
| エラー | 次にできること | 自分のせいじゃない、押せば直る | 責めない言葉、自動で3回試した事実、主ボタン1つ |

## 8. 根拠マップ（コンセプト → アートの選択 → 理由）

| コンセプトの要素 | アートの選択 | 理由 |
|---|---|---|
| 数値から考えなくていい | 色はその日の色1色、結論だけ色＋最大文字 | 読む前に色と大きさで答えが届く |
| 朝・玄関で1回開く | 紙は暖かい白、土台は朝の光のグラデーション | 朝の場面と気分が一致し、開く抵抗が下がる |
| 迷わず出られる | カードは同型・同格、ラベルはチップピル | 形が同じなら探さずに済む。種類はピルのラベルで足りる |
| 任せた、という安心 | エラーでも責めない言葉と「3回試した」の明示 | アプリ側が頑張った事実が、任せる安心を作る |

## 9. 良い例／悪い例

- 良い： 結論が青く大きい朝（寒い日）。カードは青い色付きガラスで静か。色は青だけ。
- 悪い： ダークで白透過のカードが灰色の板に見える（v0.1.5 の実機。色付きガラス化で解消、§3 v0.1.6 追記）。
- 悪い： 服装は青、傘は橙、UVは紫、と項目ごとに色を変える（色の洪水。その日の色ルール違反）。
- 悪い： 結論より先に気温の数字が目に入る（主役の転倒）。
- 悪い： 詳細画面まで色付きで賑やか（裏付けは静かであるべき）。

## 10. ダークモード方針

- 端末のダークモード設定に追従する（アプリ内トグルは置かない）。
- ダーク側の値はすべて本書の表で独立に定義する（ライトの流用禁止）。紙は #12151A、ガラスは色付きガラス（ティント白+10% @69% → ティント @59%、v0.1.6。旧： 白 19%→13% は灰色に濁るため廃止）、ふちは白 38%→6%、補助文字 #D8CFC2。土台グラデーションの上端はティントを紙へ25%寄せ（v0.1.6、§3）。
- ステータスバーの地色とアイコンの明暗もモードに合わせて切り替える。
