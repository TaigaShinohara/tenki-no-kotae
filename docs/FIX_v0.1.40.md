# FIX v0.1.40 — 雪の日の空に雨筋が混ざる不具合

2026-11-28。不具合修正のみの版（見た目の方針・色・定数は不変）。
versionName 0.1.40 / versionCode 41。

## 症状

雪の日の空で、雪片と一緒に雨筋（斜めの細い線）が薄く描かれていた。
v0.1.38（天気キャスト）・v0.1.39（アニメーション）の雪の画面
（ゴールデン home_snow、アニメ証拠フレーム）でも確認できる既存の
混入で、両版の残課題として記録されていたもの。

## 原因

`MainActivity.skyWeather()` の降水量フォールバック（補正）：

```kotlin
if (rain == 0 && e.precip >= 0.1) rain = 1
if (rain in 1..2 && e.precip >= 2.0) rain = 3
```

雪コード（71, 73, 75, 77, 85, 86）は `snow = true` を立て `rain` は
0 のままにするが、雪の時間帯も降水量を持つ（テストフィクスチャの
雪＝コード73・降水 1.2mm）ため、直後のフォールバックが発火して
`rain = 1` になり、SkyView が雨筋レイヤー（レベル1＝30本）を
雪の上に重ねて描いていた。

## 修正

フォールバック2行に `!snow` ガードを追加（MainActivity.kt、
コメント付き）。雪のときは降水量で雨を立てず、ブースト行
（2.0mm 以上で雨3）も雪では効かないよう整合させた。

- 凍雨（66, 67）など雨系コードの挙動は不変。
- みぞれ的な中間の扱いは新たに作らない。**雪コードは雪だけ**が
  今回の正解。

## 同種混入の確認（霧の判断）

霧コード（45, 48）も `rain = 0` 始まりなので、同じフォールバックで
霧の日に雨筋が出る可能性がある。ただし霧の日は実際に雨が降ることも
あり、「コードが降水を示さないのに降水量がある」ことは霧では
矛盾しない。よって**霧は現行挙動を維持**し、フォールバックを止める
のは雪のときだけとした。根拠： 雪コードは降水の「種別」まで確定
させるコードであり、降水量はその雪の量そのもの。一方で霧コードは
視程の状態を表すもので、雨の有無とは独立している。

その他の経路も確認済み： 雨レベルを降水量から導くのは skyWeather の
この1か所だけ。ウィジェットの面は天気コードのグループだけで決まり
（降水フォールバックなし）、Rules の降水判定は傘・帰り等の文章側で
空の描画とは無関係。
