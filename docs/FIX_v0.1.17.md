# v0.1.17 — 実機スクショを受けたレイアウト修正2点 記録

- 日付： 2026-11-21
- きっかけ： 本人が v0.1.16 の実機スクショ（大阪・夜21時台、服装ランク6＝ダウンの日、結論「昨日とほぼ同じ体感。ダウンで完全防備を。」）を送り、2点を指示した： **「人は画面中央に」** と **「画面上部の『昨日とほぼ同じ〜』は文字を二行に収めて見やすく」**。

## 課題 → 直し方

### 1. 今日の人が右端にいる

- 課題： 人は v0.1.15 から結論ブロック直下の右端に立っていた。本人の指示は画面中央。
- 直し方（MainActivity.showHome）： 人の行（personRow）の gravity を `Gravity.END` → **`Gravity.CENTER_HORIZONTAL`** に変更しただけ。高さ（personHeightDp 148／128／112dp）、段階表示の順（結論→人→チップ→小行）、1画面収まりの積算構造は不変。PersonView／PersonComposer 側は無変更（合成側は元々ビュー内で人物を中央に置く実装）。

### 2. 結論が文の途中で折れて4行になっている

- 課題： 実機では「昨日とほぼ同じ体／感。」「ダウンで完全防備／を。」と各文が途中で折り返し、結論が4行になっていた。原因はサイズ決定が **最長文の文字数からの段（46／42／38／34／30sp）** で、実幅を見ていなかったこと： 10文字の文に 42sp を当てると幅は約420dp になり、表示幅（約371dp）を超える。
- 直し方（MainActivity： `conclusionTextSize` を廃止し **`fitConclusion`＋`breakSentence`** を新設）：
  1. **実測**： 結論と同じ太字フェイス（Typeface.DEFAULT_BOLD）の Paint で各文を基準サイズ（100sp）で測り（幅はサイズに線形）、「その文が表示幅に1行で収まるサイズ」＝ 100 × 表示幅 ÷ 実測幅 を文ごとに求める。表示幅は画面幅 − ルート左右余白 40dp、フェイス差の安全マージン 2% を引く。
  2. **統一**： 結論全体のサイズは全丈の最小値（2文でサイズがバラバラにならない）。上限は従来の最上段と同じ **46sp**。
  3. **下限 24sp**： 統一サイズが 24sp を下回る場合、下限で収まらない文だけ **文節の区切りで1回改行** する（後述）。ただし改行で結論が3行を超える場合（＝両文とも下限で収まらない場合）は、改行せず **下限未満の実測フィット** を選び、2行の基本形を守る。
  4. 改行位置（`breakSentence`）： 左右の実測幅のバランスが最良の位置を基本とし、最良比の 15% 以内にある候補の中では **文節の切れ目（は／が／を／に／の／な／と／も／＋／／ の直後）** を優先する。例： 「トレーナー＋｜ライトアウターで。」「昨日とは別世界な｜くらい暖かい。」。
- ハロー（setShadowLayer、半径16dp）は従来どおり結論の各 TextView に適用（無変更）。

## 結論フォントサイズの検証（実測計算）

グリフ幅は Noto Sans CJK Bold の実アドバンスで全パターンを測定した（日本語グリフは全て 1.00em、「OK」のみプロポーショナル）。Rules が出しうる結論文は文1が14種・文2が7種で、最長はどちらも **15.00em**：

| 文 | 幅 |
|---|---|
| 昨日とは別世界なくらい暖かい。（文1・最長） | 15.00em |
| 昨日とは別世界なくらい寒い。 | 14.00em |
| 今日は過ごしやすい暖かさ。 | 13.00em |
| トレーナー＋ライトアウターで。（文2・最長） | 15.00em |
| ニット＋コートで正解。／冬コート＋マフラーで。 | 11.00em |
| 昨日とほぼ同じ体感。／ダウンで完全防備を。（今回のスクショ） | 10.00em |
| 半袖でOK。（文2・最短） | 5.46em |

最長ペア（15em＋15em）は実際に起こりうる： 「別世界なくらい暖かい」は前日比 +10℃ 以上、「トレーナー＋ライトアウター」は日中体感 13〜18℃ の日 — 急に暖かくなった晩秋の日（今日15℃・昨日4℃）で両立する。机上の最悪ではなく実在の組合せとして検証した。

決定サイズと行数（表示幅 ＝ 画面幅 − 40dp、マージン 2% 適用後）：

| 画面幅 | ケース | 決定サイズ | 行数 |
|---|---|---|---|
| 411dp（想定実機） | 今回のスクショ（10em＋10em） | **36.4sp**（旧方式は 42sp で各文が折れて4行） | 2 |
| 411dp | 最長ペア（15em＋15em） | **24.2sp**（下限 24sp 以上で収まる） | 2 |
| 411dp | 典型ペア（10em＋11em） | 33.1sp | 2 |
| 375dp | 混合ペア（15em＋11em） | 24sp ＋ 最長文を文節改行 | 3 |
| 360dp（設計最小） | 最長ペア（15em＋15em） | **20.9sp**（両文改行すると4行になるため、下限未満フィットで2行を優先） | 2 |
| 360dp | 混合ペア（15em＋11em） | 24sp ＋ 最長文を文節改行 | 3 |
| 320dp（旧世代） | 最長ペア | 18.3sp（同上） | 2 |

- 改行時の半分の幅チェック： 「昨日とは別世界な｜くらい暖かい。」は 8em／7em → 24sp で 192dp／168dp、360dp幅の表示幅 313.6dp に収まる。「トレーナー＋｜ライトアウターで。」は 6em／9em → 144dp／216dp で収まる。
- フォント倍率（scaledDensity）は実測・表示の両方が同じ係数を通るため、倍率を上げても「1行に収まる」関係は保たれる（1画面の高さ方向の収まりは従来どおり倍率1.0基準の見積もり）。

## コントラストの担保（不変性の監査）

- v0.1.13 の走査スクリプト自体はリポジトリに保存されていないため、数値走査の再実行ではなく **入力の不変性監査** で担保した。本版で変更したのは結論のサイズ決定と人の配置だけで、走査の入力は全て無変更： アクセント色（帯別のトーン表）、空（SkyView のグラデーション・グロー・雲）、ハロー（色・α・半径16dp）、文字色。WCAG のコントラスト比にフォントサイズの項はない。
- サイズに依存する唯一の要素はゲート区分（大きな文字＝3:1）で、本プロジェクトの規約では太字 14sp 以上が大きな文字。結論は太字で、到達しうる最小サイズは下限経路で 24sp、例外経路（下限未満フィット）でも設計最小幅 360dp で 20.9sp、320dp 幅でも 18.3sp — 全経路で大きな文字の区分を維持する。
- よって v0.1.13 走査の結果がそのまま有効： 結論の最弱 **ライト 3.75／ダーク 5.79**（ゲート 3.0）で合格。むしろサイズが下がる分、グリフがハローの内側に収まる割合は下がらない。

人の配置変更は高さを変えないため、効くのは結論の高さだけ。結論の高さの上限は max（2行 × 46sp、3行 × 24sp）＝ 2×56＋先頭余白10 ＝ **122dp**（到達可能なペアでは最長文が最低 9em あるため、表示幅 371dp 以下では実上限は約108dp まで下がるが、積算は保守側の 122dp で行う）。従来と同じ物差し（フォント倍率1.0）：

- 最小想定（高さ620dp）： ルート余白 32 ＋ 地点名 21 ＋ 結論 122 ＋ gapNote 34 ＋ 人 128＋上マージン 6 ＋ チップ列 116 ＋ 小行群（最大）140 ＝ **599dp ≦ 620dp** ✓（v0.1.15 の 611dp から改善）
- 標準想定（高さ700dp）： 余白 32 ＋ 地点名 21 ＋ 結論 122 ＋ gapNote 34 ＋ 人 148＋6 ＋ チップ 116 ＋ 小行 140 ＝ **619dp ≦ 700dp** ✓（同 651dp）
